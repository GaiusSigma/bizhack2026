Offer Studio API

Wszystko, co robi interfejs, da się zrobić przez REST/JSON. Slajdy, podgląd i PDF renderuje FigCraft z biblioteki slajdów (pliki .figcraft/JSON). Każda zmiana odświeża otwarte podglądy ofert.

Logowanie

Authorization: Bearer <STUDIO_API_TOKEN> (skrypty, n8n) albo Basic auth z hasłem STUDIO_PASSWORD (dowolny login).

Bloki wiedzy

GET /api/blocks?type=&tag=&q=Lista, z filtrami
POST /api/blocksNowy blok albo tablica bloków. type wymagany; opcjonalnie własne id
GET /api/blocks/:idJeden blok
PATCH /api/blocks/:idZmiana pól. data jest scalane (klucz = null usuwa pole); ?replace=1 zastępuje całe data
DELETE /api/blocks/:idUsunięcie
GET /api/metaTypy i tagi w użyciu, adres FigCraft web
curl -X POST $URL/api/blocks -H "Authorization: Bearer $TOKEN" -H "content-type: application/json" -d '{
  "id": "uc-due-diligence",
  "type": "use_case",
  "title": "Due diligence spółki",
  "body": "Gaius przegląda dokumenty spółki i zbiera ryzyka w raport.",
  "data": { "effect": "krótszy czas przeglądu i pełna lista ryzyk." },
  "tags": ["vault", "kancelaria"]
}'

Oferty i slajdy

GET /api/offersLista ofert
POST /api/offers{name, data, slides?: [...]}
GET /api/offers/:idOferta ze slajdami
PATCH /api/offers/:idNp. {"data": {"client": "ACME S.A.", "price": "12 000"}}
POST /api/offers/:id/duplicateKopia oferty ze slajdami (opcjonalnie {name})
DELETE /api/offers/:idUsunięcie oferty i jej slajdów
POST /api/offers/:id/slides{frame, data, block_ids?, query?, position?}; frame to nazwa slajdu w bibliotece
PATCH /api/slides/:idZmiana slajdu (data scalane jak w blokach)
DELETE /api/slides/:idUsunięcie slajdu
PUT /api/offers/:id/order{"ids": [...]}: nowa kolejność wszystkich slajdów
GET /api/offers/:id/previewRender podglądu (PNG każdego slajdu): {key, ms, slides: [{id, frame, hidden, url, error?}]}
GET /api/offers/:id/pdfPDF z FigCraft (?download=0 otwiera w przeglądarce); ukryte slajdy pomija
GET /api/offers/:id/figcraftGotowa oferta jako plik .figcraft do ręcznych poprawek

Bloki na slajdzie: block_ids (konkretne bloki w tej kolejności) albo query, np. {"type": "use_case", "tag": "kancelaria", "limit": 6}.

curl -X PATCH $URL/api/offers/gaius-vault-bazowa -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" -d '{"data": {"client": "ACME S.A."}}'

curl -o oferta.pdf $URL/api/offers/gaius-vault-bazowa/pdf -H "Authorization: Bearer $TOKEN"

Biblioteka slajdów (FigCraft)

GET /api/libraryWszystkie slajdy: [{frame, source, source_name, width, height, fields, slots, thumb}]
GET /api/templatesPliki ze slajdami (z listą slajdów każdego pliku)
GET /api/templates/:id/filePlik .figcraft do edycji w FigCraft
POST /api/templatesmultipart: file (.figcraft, .json, .fig, .penpot, .sketch, .svg), opcjonalnie id i name. Istniejące id = podmiana pliku
POST /api/templates?id=&name=z content-type: application/json: sam JSON strony/dokumentu FigCraft (albo Figma REST API)
PATCH /api/templates/:id{"name": "..."}
DELETE /api/templates/:idUsunięcie pliku i jego slajdów z biblioteki

Każda ramka najwyższego poziomu (ze wszystkich stron) to slajd; nazwa ramki musi być unikalna w całej bibliotece (konflikt = 409). Pola wiąże się nazwami warstw: {{data.title}} (treść slajdu), {{offer.client|upper}} (zmienna oferty), #item (karta na blok, w środku {{title}}, {{body}}, {{n}} i pola bloku, np. {{effect}}), #item:lines (wiersz z pola data.lines: etykieta | wartość), [[2:tekst]] (styl 2. wyróżnienia). W treści **słowo** dostaje styl 1. wyróżnienia. Pusty wynik ukrywa warstwę.

curl -X POST $URL/api/templates -H "Authorization: Bearer $TOKEN" -F file=@case-study.figcraft

curl -X POST "$URL/api/templates?id=case-study&name=Case%20study" -H "Authorization: Bearer $TOKEN"   -H "content-type: application/json" --data-binary @case-study.json

Komponenty (wymienne karty) i dobór przez AI

Ramka najwyższego poziomu nazwana @zestaw (np. @dlaczego) nie jest slajdem, tylko zestawem kart: każda ramka w środku to gotowa karta (własna ikona, kolor, układ), nazwa = klucz. Id karty: zestaw/klucz (po slugify). Na slajdzie miejsca na karty nazywa się #pick:zestaw. Wybrane karty wchodzą w miejsce slotów w kolejności wyboru; bez wyboru slajd pokazuje to, co narysowano. Teksty kart nazwane {{title}}, {{body}}… można nadpisać; bez wartości zostaje tekst z rysunku.

Opisy kart siedzą w SQLite (tabela components): co karta pokazuje, kiedy ją wybrać, kiedy nie, temat (warianty jednego argumentu), wariant, tagi. Wiersze zakłada synchronizacja z biblioteką przy wgraniu pliku; opisy zostają przy podmianie pliku. Zasady zestawu: tabela component_sets.

GET /api/components?set=&missing=1Karty z opisami i miniaturą (missing=1: także te, których już nie ma w bibliotece)
GET /api/components/:zestaw/:kluczJedna karta
PATCH /api/components/:zestaw/:kluczOpis: title, description, use_when, avoid_when, topic, variant, tags, data (data = stałe nadpisania pól karty)
GET /api/component-setsZestawy z zasadami
PATCH /api/component-sets/:id{"title": "...", "rules": "Dokładnie 6 kart, jedna wyróżniona…"}
PATCH /api/slides/:idRęczny wybór: {"picks": {"dlaczego": [{"component": "dlaczego/on-premise", "data": {"title": "…"}}, …]}}
GET /api/slides/:id/pick-contextWszystko, czego potrzebuje agent do wyboru: oferta, slajd, liczba slotów, zasady i opisy kart (np. dla n8n z własnym modelem)
POST /api/slides/:id/pickDobór przez Claude: {"brief": "bank, boją się chmury", "apply": true} → {picks, note, warnings, slide}. apply: false tylko podpowiada. Wymaga ANTHROPIC_API_KEY
curl -X POST $URL/api/slides/s-dlaczego/pick -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" -d '{"brief": "Bank, regulowany przez KNF, zarząd boi się chmury"}'

Eksport i import

GET /api/exportCała baza (bloki, szablony z plikami w base64, oferty, slajdy) w jednym JSON
POST /api/import?mode=mergeScalenie: nadpisuje rekordy o tych samych id, resztę zostawia
POST /api/import?mode=replaceZastąpienie całej bazy zawartością pliku

Opis maszynowy

GET /api/openapi.json to opis API w formacie OpenAPI 3.1, budowany z tras serwera. Z niego korzysta węzeł n8n „Offer Studio”: nowe endpointy widzi bez przebudowy n8n.

Na żywo

GET /api/events to strumień Server-Sent Events z informacją o każdej zmianie ({table, id, offer_id}).
