Offer Studio API

Everything the UI does can be done over REST/JSON. Slides, previews and PDFs are rendered by FigCraft from the slide library (.figcraft/JSON files). Every change refreshes any open offer previews.

Authentication

Authorization: Bearer <STUDIO_API_TOKEN> (scripts, n8n) or Basic auth with the password STUDIO_PASSWORD (any username).

Knowledge blocks

GET /api/blocks?type=&tag=&q=List, with filters
POST /api/blocksA new block or an array of blocks. type is required; a custom id is optional
GET /api/blocks/:idA single block
PATCH /api/blocks/:idUpdate fields. data is merged (key = null deletes the field); ?replace=1 replaces the whole data
DELETE /api/blocks/:idDelete
GET /api/metaTypes and tags in use, FigCraft web URL
curl -X POST $URL/api/blocks -H "Authorization: Bearer $TOKEN" -H "content-type: application/json" -d '{
  "id": "uc-due-diligence",
  "type": "use_case",
  "title": "Company due diligence",
  "body": "Gaius reviews the company documents and collects the risks into a report.",
  "data": { "effect": "shorter review time and a complete list of risks." },
  "tags": ["vault", "law-firm"]
}'

Offers and slides

GET /api/offersList of offers
POST /api/offers{name, data, slides?: [...]}
GET /api/offers/:idAn offer with its slides
PATCH /api/offers/:idE.g. {"data": {"client": "ACME Ltd", "price": "12,000"}}
POST /api/offers/:id/duplicateCopy of an offer with its slides (optionally {name})
DELETE /api/offers/:idDelete an offer and its slides
POST /api/offers/:id/slides{frame, data, block_ids?, query?, position?}; frame is the slide name in the library
PATCH /api/slides/:idUpdate a slide (data is merged as for blocks)
DELETE /api/slides/:idDelete a slide
PUT /api/offers/:id/order{"ids": [...]}: the new order of all slides
GET /api/offers/:id/previewRender a preview (a PNG of each slide): {key, ms, slides: [{id, frame, hidden, url, error?}]}
GET /api/offers/:id/pdfPDF from FigCraft (?download=0 opens it in the browser); hidden slides are skipped
GET /api/offers/:id/figcraftThe finished offer as a .figcraft file for manual touch-ups

Blocks on a slide: block_ids (specific blocks in that order) or query, e.g. {"type": "use_case", "tag": "law-firm", "limit": 6}.

curl -X PATCH $URL/api/offers/gaius-vault-base -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" -d '{"data": {"client": "ACME Ltd"}}'

curl -o offer.pdf $URL/api/offers/gaius-vault-base/pdf -H "Authorization: Bearer $TOKEN"

Slide library (FigCraft)

GET /api/libraryAll slides: [{frame, source, source_name, width, height, fields, slots, thumb}]
GET /api/templatesSlide files (each with its list of slides)
GET /api/templates/:id/fileThe .figcraft file, for editing in FigCraft
POST /api/templatesmultipart: file (.figcraft, .json, .fig, .penpot, .sketch, .svg), optionally id and name. An existing id = replace the file
POST /api/templates?id=&name=with content-type: application/json: the raw JSON of a FigCraft page/document (or of the Figma REST API)
PATCH /api/templates/:id{"name": "..."}
DELETE /api/templates/:idDelete the file and its slides from the library

Every top-level frame (across all pages) is a slide; frame names must be unique across the whole library (a conflict = 409). Fields are bound by layer names: {{data.title}} (slide content), {{offer.client|upper}} (offer variable), #item (a card per block, containing {{title}}, {{body}}, {{n}} and the block's fields, e.g. {{effect}}), #item:lines (a row from the data.lines field: label | value), [[2:text]] (the style of the 2nd highlight). In content, **word** gets the style of the 1st highlight. An empty result hides the layer.

curl -X POST $URL/api/templates -H "Authorization: Bearer $TOKEN" -F file=@case-study.figcraft

curl -X POST "$URL/api/templates?id=case-study&name=Case%20study" -H "Authorization: Bearer $TOKEN"   -H "content-type: application/json" --data-binary @case-study.json

Components (interchangeable cards) and card picking by AI

A top-level frame named @set (e.g. @why) is not a slide but a set of cards: every frame inside it is a ready-made card (its own icon, colour, layout), and its name is the key. A card's id is set/key (slugified). On a slide, card placeholders are named #pick:set. Picked cards fill the slots in the order they were picked; with nothing picked, the slide shows what was drawn. Card texts named {{title}}, {{body}}… can be overridden; with no value, the drawn text stays.

Card descriptions live in SQLite (the components table): what the card shows, when to pick it, when to avoid it, its topic (variants of one argument), variant and tags. Rows are created by syncing with the library when a file is uploaded; descriptions are kept when the file is replaced. Set rules: the component_sets table.

GET /api/components?set=&missing=1Cards with descriptions and a thumbnail (missing=1: also those no longer in the library)
GET /api/components/:set/:keyA single card
PATCH /api/components/:set/:keyDescription: title, description, use_when, avoid_when, topic, variant, tags, data (data = fixed overrides of the card's fields)
GET /api/component-setsSets with their rules
PATCH /api/component-sets/:id{"title": "...", "rules": "Exactly 6 cards, one highlighted…"}
PATCH /api/slides/:idManual picks: {"picks": {"why": [{"component": "why/on-premise", "data": {"title": "…"}}, …]}}
GET /api/slides/:id/pick-contextEverything an agent needs to pick cards: the offer, the slide, the number of slots, rules and card descriptions (e.g. for n8n with its own model)
POST /api/slides/:id/pickCard picking by Claude: {"brief": "bank, wary of the cloud", "apply": true} → {picks, note, warnings, slide}. apply: false only suggests. Requires ANTHROPIC_API_KEY
curl -X POST $URL/api/slides/s-why/pick -H "Authorization: Bearer $TOKEN" \
  -H "content-type: application/json" -d '{"brief": "Bank regulated by the financial supervisor, the board is wary of the cloud"}'

Export and import

GET /api/exportThe whole database (blocks, templates with files in base64, offers, slides) in one JSON
POST /api/import?mode=mergeMerge: overwrites records with the same ids, leaves the rest untouched
POST /api/import?mode=replaceReplace the whole database with the contents of the file

Machine-readable spec

GET /api/openapi.json describes the API in OpenAPI 3.1, built from the server's routes. The "Offer Studio" n8n node uses it, so it picks up new endpoints without rebuilding n8n.

Live updates

GET /api/events is a Server-Sent Events stream announcing every change ({table, id, offer_id}).
